# 学习指南

## 每题工作流程

1. 阅读 exercise_catalog.md，手算至少两个例子并检查返回类型、排序规则与空输入。
2. 运行单题测试，确认当前结果是 TODO 的 xfail；不要通过修改测试来完成题目。
3. 在 exercises/ 中替换 TODO，保留签名和类型提示；优先选择合理数据结构。
4. 用 `python -m pytest 路径 -k 题目 --strict-exercises` 验证；至少补充一个你想到的边界。
5. 解释复杂度、内存开销和为什么选择这个标准库或向量化操作。

## 项目工作流程

先阅读独立 README，运行生成数据和项目命令。随后按输入、核心处理、输出、CLI 的顺序读源码，关闭参考实现独立重做，再比较行为。项目是完整参考实现，练习仍保留待完成骨架。

Phase 1 练习与项目主要使用标准库。Phase 2 项目不调用 exercises/，方便独立学习与测试。所有路径示例均相对于仓库根目录；通过 editable 安装后，模块入口也可用于其他工作目录，但请为数据提供正确路径。

## 反馈与进度

默认 xfail 只表示练习尚未实现，不计入已完成。实现后的错误与异常仍是失败。严格模式用于最终学习验收，完整项目测试用于仓库工程验收。测试参数覆盖正常、空输入及边界；浮点结果使用容差，随机过程固定种子。

## 数据复现

`python scripts/generate_datasets.py --seed 42` 生成全部离线数据。仅用 Python/NumPy/Pillow 时选择 `--only core`，省略分类 CSV。相同种子与依赖版本的结果可复现，跨 NumPy/sklearn 版本不承诺字节一致。模拟电商数据含有意损坏记录，不应在分析前手动删除。

## 常见问题

导入失败通常意味着当前解释器未激活仓库虚拟环境或尚未执行 editable 安装。图形默认使用 Agg，不需要桌面窗口。文件写入项目可能拒绝覆盖，请更换输出路径；分析报告允许重建。完整依赖验证和当前环境的限制见 validation.md。
